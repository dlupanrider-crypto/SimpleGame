# 准点撤离：首版玩法规格

> 实施状态：首版草稿已可试玩，本文是目标设计，实际完成范围和差异以 [执行计划](PLAN.md) 为准。

特性 ID：`pingan-monopoly`；提案版本：`office-escape@1.0.0`；状态：`active`；更新：2026-10-29。

本文细化 [主设计](DESIGN.md)，用于评审和后续实现。所有地图、规则、事件与数值目前都是草案，尚无正式发布版本。**这里的“大富豪”按对话上下文暂理解为大富翁「准点撤离」；若指扑克牌游戏，需另立设计。**

## 1. 体验与目标

玩家在到点下班时从工位出发，规划路线、观察高危区域、处理职场事件，争取不被叫住而走到电梯或出口。路线短不等于一定好：高危格会提高被发现风险。隐藏的体面评价用于同轮成功时的比较，不决定能否撤离。

固定 4 个玩家席位，支持 1～4 名真人，不足的席位在开局时由机器人补足；目标支持 30 轮以上，默认上限 40 轮，实际用时待测试。每人独立成功或失败；先到达的人进入观战，其他人继续。被叫住、被安排临时任务、被拉去开会或风险达阈值立即返回工位，本局失败。到第 40 轮仍未到达终点也失败。

## 2. 三层办公楼地图

地图已由单层 5×5 草案调整为三层、每层 7×7 的长局方案。完整布局、图例、分岔、楼梯、检查点、事件与安静节点见 [长局地图设计](MAP_DESIGN.md)；该文档是具体地图坐标的权威来源。起始工位为第一层 `(7,1)`，电梯和出口均在第三层。

玩家可查看已知风险、选择路径和安静节点，但不能预知牌堆；楼梯开放前须先经过本层检查点。路线和机器人策略应确保实际对局有 30 轮以上的可玩空间，目标仍需模拟和真人验收。

## 3. 回合与状态机

玩家状态：`active`、`escaped`、`failed`；风险初始 0，达到 4 立即失败；体面初始 3，上限 5、下限 0。风险不能低于 0；不将风险达到 4 后再降回去当作成功。

房间状态：`waiting → rolling → choosing_path → resolving → waiting_choice → turn_end → ... → finished`。其中 `waiting_choice` 仅在事件需要选择时进入；客户端只显示当前阶段可用操作。

1. 房主选择版本及内容模式，邀请成员；1～4 名真人均可开始，开局时补足至 4 席。按真人加入顺序排列，再按机器人编号补位；固定席位、身份和顺序，进行中不允许额外玩家加入对局或替换席位。
2. 当前玩家点击一次掷骰，房主生成 1～6 的整数并广播，1～3 映射 1 步、4～6 映射最多 2 步，之后进入选路。玩家选择 1 到本次移动额度之间的相邻路径，可以提前停下，可以回头；目标格或墙不可继续穿越，路径可在确认前修改。
3. 确认后房主检查每一步：起点必须匹配当前位置，长度、相邻性、通行性、玩家和阶段必须合法，才能执行。其他玩家可看见路径与实际风险。重复确认不得重复扣算。
4. 每进入一格按顺序先加该格风险；若达到 4，立即失败并结束路径。未失败且进入终点，立即成功，不执行剩余路径。否则继续移动。
5. 在非终点落点为事件格时，从共享牌堆抽一张符合条件的卡。先展示事件文本与效果；无选择的卡自动执行，需要选择的卡等待当前玩家确认。涉及事件移动时，逐步应用相同风险与终点顺序；额外事件落点最多触发一次，不递归连锁；安静节点按地图文档限次恢复。
6. 执行完进入回合结束；下一位 `active` 玩家行动。所有当轮 `active` 玩家各行动过一次后，轮数加一。第 40 轮最后一位行动结束后仍 `active` 的玩家判为超时失败。

机器人由房主以相同动作接口和规则控制；每步仅依据公开地图、当前位置和已知风险选路，不预知牌堆、骰子或其他隐藏信息。允许通过策略与随机选择形成不同路径，但必须保证合法；机器人自动处理事件选择并广播结果。界面区分真人与机器人并显示其操作，不为拖慢游戏加入长等待。真人掉线不自动接管为机器人。

房主权威校验动作的 `game_id`、序号、玩家、阶段、骰子额度和地图版本；非法、过期或重复动作不改变状态。选路和事件选择没有自动倒计时：房主不能替玩家做决定；玩家断线后按断线规则处理。

## 4. 撤离与体面结算

- 风险达到 4，或事件明确写“被叫住/临时任务/会议”：当前位置移回第一层工位 `(7,1)`，状态设为 `failed`，保留失败原因，不允许继续移动。
- 风险未达 4 且进入终点：立即设为 `escaped`，记录完成轮数、顺序、体面和终点。成功玩家不再参与事件目标选择。
- 玩家超时未撤离：状态为 `failed`，原因 `timeout`；为展示一致，棋子回到工位。撤离和失败玩家仅观战。
- 成功优于失败；成功者按完成轮数升序、体面降序，仍相同并列。行动先后不用于打破并列。失败玩家显示原因，不做强制名次排序。
- 体面 4～5 为“从容离场”，2～3 为“低调撤离”，0～1 为“动静有点大”；这是评价，任一体面值均可撤离。体面数值用于同轮排名，但过程只显示“从容/略显紧张”等变化反馈，结算时显示数值和评价。

## 6. 游戏页面

- **大厅**：游戏卡片「平安同行：准点撤离」；房间创建时选版本和可选吐槽，显示目标轮数及规则说明（时长待实测），并展示四个席位及预计机器人数量。
- **房间**：左侧地图标注当前位置、路径、高危与出口；右侧列出玩家状态、回合数、当前行动者和事件记录。当前玩家的路径确认和事件选择是显式操作。
- **风险反馈**：地图以文字、图标及颜色区分高危；移动预览显示每格风险，但不会预告随机卡面。到终点前若风险达到 4，预览应明确显示无法成功。
- **结算**：按规则显示成功/失败、出口、用时轮数、失败原因和体面评价；再次开局保留所选版本，但重新初始化棋盘、牌堆及玩家状态。
- **窄屏与无障碍**：棋盘可横向滚动或缩放，格点保留文本标签、焦点和键盘操作，状态不只依赖颜色。

## 7. 版本与数据契约

首版完整内容冻结后标记 `office-escape@1.0.0`，包含 `engine_protocol`、地图节点与边、高危数值、牌池、题目、文本素材版本、默认内容开关和规则参数。用规范化 JSON 计算 SHA-256；规范化规则在实现时固定并纳入测试。版本号或哈希任何一项不同即不兼容；哈希只用于一致性检测。

建房、房间公告、邀请、加入和开局均携带版本 ID、哈希、协议与内容开关。玩家缺包或不兼容时拒绝加入并提示升级；游戏开始后不能切换版本，扩展更新不应改变正在进行的对局。插件没有服务端和自动包下载，版本包随插件分发，旧客户端提示能力需实测。旧版地产设计从未发布，不作为已交付版本出现。

后续调整文字、地图、事件概率或参数，均生成新版本并保留旧包；可发布“更多路线”“团队协作”等独立版本。公开版本不原地覆盖；草稿在确认前可修改。

## 8. 断线与验收

非房主断开时暂停其回合或未决选择，房主可等待或明确确认将其判为退出失败；现有传输层是否支持身份重连、超时和重连中状态恢复须先实现并验证，不能只写在 UI 上。房主关闭页面终止当前对局；不承诺房主迁移或继续未完成棋局。

验收应覆盖地图 BFS 连通、每条经过高危的风险、可提前停止、终点与失败顺序、分叉、骰子边界、40 轮结算和并列；全部 30 张事件、选择、范围截断、抽牌和重新洗牌；版本/哈希不一致、已开局冻结、旧版兼容；重复消息、无权操作、网络中断及退出。还需多浏览器页面、窄屏和至少两台真实设备联机验证，记录骰子及强制失败卡对平均时长和体验的影响。

尚待用户确认：事件强度、40 轮限制、地图美术以及“体面作为同轮排序”是否符合预期。确认前不将本草案称为已交付规则。
